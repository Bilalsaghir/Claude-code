Agent Responsibilities

📈 Market Research

Sizes the addressable market, identifies monetisation models used by similar apps, and benchmarks revenue potential.

TAM / SAM Monetisation Revenue signals

⚙️ Technical Feasibility

Assesses tech stack requirements, third-party API dependencies, build complexity, and known engineering risks.

Stack APIs needed Build effort

🧑‍🤝‍🧑 User Personas

Identifies target user segments from social signals and forum research, surfaces pain points and willingness-to-pay signals.

Segments Pain points WTP signals

🔍 Competitor Analysis

Scrapes App Store / Play Store for direct competitors, reviews their ratings and reviews, and maps feature gaps and moats.

Direct comps Feature gaps Moats

📅 Trend & Timing

Analyses Google Trends, social buzz, and recent news to gauge whether timing is early, peak, or saturated.

Search trends Social buzz Timing verdict

📝 Synthesis Agent

Merges all agent findings, scores the idea across dimensions, flags top risks, and recommends concrete next steps.

Idea score Risk flags Next steps

Data Flow

  • User submits idea + constraints
  • Orchestrator decomposes into tasks
  • 5 agents run in parallel
  • Findings merge into shared memory
  • Synthesis agent scores & reports

Open Questions annotate to resolve

  • ? Should agents run fully in parallel or with a dependency ordering (e.g. persona before market sizing)?
  • ? What is the timeout / retry policy for slow external APIs (App Store scraping, social APIs)?
  • ? Should the memory store persist across sessions (long-term knowledge base) or be ephemeral per idea?
  • ? How is deduplication handled when multiple agents surface the same competitor or source?
